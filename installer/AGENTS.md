# installer/: the one step Mac installer

Read the root [`AGENTS.md`](../AGENTS.md) first, then [`NOTES.md`](NOTES.md).
User facing details are in [`macos/README.md`](macos/README.md).

## Purpose

This is the most important code in the funnel. A stranger downloads it, runs
one thing, and minutes later their Mac answers their team. If it fails or asks
a confusing question, we lose them.

## Files

| File | What |
|---|---|
| `macos/install-starferret.sh` | The installer. Nine steps, idempotent, supports `--dry-run` and `--uninstall`. |
| `macos/build-release.sh` | Builds `dist/starferret-macos.tar.gz` (source plus built web UIs), copies `install-starferret.sh`, writes `dist/SHA256SUMS`. |
| `macos/app/` | The StarFerret Mac app (Swift, SwiftUI): install window with progress, then a menu bar item. `InstallerLine.swift` parses the script's output, `Installer.swift` runs it, `StarFerretApp.swift` is the UI, `Info.plist` is a template. |
| `macos/build-dmg.sh` | Compiles the app with `swiftc`, packs `install-starferret.sh` and the release bundle inside it, signs it, notarizes when the `NOTARY_*` variables are set. Signed: `dist/StarFerret.dmg`. Without `STARFERRET_SIGN_ID`: ad hoc, `dist/StarFerret-early-access.dmg` with `early-access.md` inside as "How to open StarFerret.txt". |
| `macos/early-access.md` | How testers open the early access `.dmg`. Also the top of the release notes. Keep it true to current macOS. |
| `macos/build-librechat.sh` | Builds `dist/librechat-<version>-darwin-arm64.tar.gz`. Needs Apple silicon and Node.js 24. Downloads 1 to 2 GB, so ask before running it. |
| `../.github/workflows/release.yml` | On a `v*` tag: runs both build scripts on `macos-15` and publishes the release. |
| `macos/README.md` | What it does, flags, services, logs. Keep it in sync with the script. |

## Non negotiable rules

1. **bash 3.2 only.** macOS ships `/bin/bash` 3.2. No associative arrays, no
   `${var,,}`, no `mapfile`, no `&>>`, no `[[ =~ ]]` capture tricks you have
   not tested. Always test with `/bin/bash`, not Homebrew bash or zsh.
2. **No sudo. No password prompt. Ever.** Everything installs under the user's
   home, `/Applications`, or `~/Library/LaunchAgents`.
3. **No Docker requirement.** Docker Desktop needs a paid license at this
   customer size and an admin install. Apps in the free path run natively.
4. **No account, no sign in, no telemetry.**
5. **Every state changing command goes through `run`** (or checks `DRY_RUN`),
   so `--dry-run` changes nothing. If you add a step, add its dry run branch.
6. **Idempotent.** Running it twice must be safe and must upgrade in place.
   Never delete or overwrite `data/`.
7. **Fail with a sentence a non engineer can act on.** Use `die "what failed
   and what to do next"`. Never leave a raw stack trace as the last line.
8. **Works piped.** `curl ... | bash` has no `BASH_SOURCE` file and no stdin.
   Never `read` from the user. Never assume the script sits in a checkout.
9. **Do not kill things you did not start.** If a port is busy, stop and say
   so. Only stop LaunchAgents with our own labels.
10. **Keep the step list in sync:** the script header, the `step` calls, and
    `macos/README.md`. The marketing site, kept elsewhere, shows the same
    steps; if you change them, say so in your report so it can be updated.
11. **The Mac app reads the script's output.** `macos/app/InstallerLine.swift`
    understands `[n/9] Title`, `Downloading <model>: N% (detail)`, `✓ ...`,
    `! ...`, and `Install stopped. ...`. If you change how `step`, `ok`, `warn`,
    `die`, or the download line print, change the parser too.
12. **The app never changes the Mac itself.** Everything goes through
    `install-starferret.sh`, so the Terminal install and the app stay one install path.

## How it is built

- Private Python via `uv` (`uv venv --python 3.12`), so never rely on the
  system Python.
- LibreChat and n8n run on a private Node.js in `~/.starferret/node`.
  LibreChat's database is a private MongoDB on 127.0.0.1:27410.
- Five LaunchAgents: `com.starferret.supervisor`, `com.starferret.board`,
  `com.starferret.mongodb`, `com.starferret.librechat`, `com.starferret.n8n`.
  Plists are generated by `write_plist`. Loaded with
  `launchctl bootstrap gui/<uid>`, stopped with `bootout`.
- Ollama goes to `/Applications`, or `~/Applications` when that is not
  writable (`place_ollama_app`). Never ask for a password to get it there.
- Release downloads (the app, ready built LibreChat) go through
  `verify_release_file`, which checks the release's `SHA256SUMS`. A mismatch
  stops the install; a missing file only warns.
- `LIBRECHAT_VERSION` in `install-starferret.sh` is the one place the LibreChat version
  lives. `build-librechat.sh` reads it from there.
- Control writes `data/control/setup-token` until its first admin exists. The
  summary prints it as a one time `?setup=` link. Never print it anywhere else.
- The model download is step 8, last, and goes through Control's
  `/api/control/models/pull` with the `X-StarFerret-Local-Key` header (the
  key is `data/control/local-key`, mode 600). The window polls
  `/models/pulls`. If Control cannot take it, the window runs `ollama pull`.
  Save the Board's model only after the download, since the Board rejects a
  model Ollama does not have.
- Model is chosen by memory in step 1. The names must stay on the Board's
  failover ladder in `server/ollama_client.py`.
- A natively installed app is made visible to Control by a `launchd:` field in
  its `catalog/*.yaml`. See `../catalog/AGENTS.md`.
- Install location: the checkout it runs from, or `~/.starferret/app`.
- Anything the installer adds outside `~/.starferret` (Ollama, uv, a model)
  goes through `remember`, so `--uninstall --everything` can remove it and
  nothing else. If you add a step that installs something, record it too.
  `--everything` never deletes a checkout's `data/`.

## Verify

```bash
/bin/bash -n installer/macos/install-starferret.sh                 # syntax
/bin/bash installer/macos/install-starferret.sh --dry-run          # from a checkout
cat installer/macos/install-starferret.sh | /bin/bash -s -- --dry-run   # piped mode
/bin/bash installer/macos/install-starferret.sh --uninstall --dry-run
/bin/bash installer/macos/install-starferret.sh --uninstall --everything --dry-run
```

After a dry run, confirm nothing was created:
`ls ~/Library/LaunchAgents | grep starferret` should print nothing new.

If you change `write_plist`, generate a plist to a temp folder and check it
with `plutil -lint`.

**Do not run a real install without being asked.** A dry run is
not proof the real path works. Say clearly which of the two you ran.

For the Mac app (needs `dist/starferret-macos.tar.gz` from `build-release.sh`):

```bash
bash installer/macos/build-dmg.sh
# Run the built app against a stand-in script so nothing is installed:
hdiutil attach dist/StarFerret.dmg -nobrowse -mountpoint /tmp/sf-dmg
STARFERRET_INSTALL_SCRIPT="$PWD/installer/macos/app/fake-install.sh" STARFERRET_AUTOSTART=1 \
  /tmp/sf-dmg/StarFerret.app/Contents/MacOS/StarFerret
hdiutil detach /tmp/sf-dmg
```

**Never click Install in a test build without a stand-in script.** The app
carries the real installer.

Then update `NOTES.md`.
